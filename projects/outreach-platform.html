06 / CONTACTS → SHARED WORKSPACE

Journalist outreach platform

I interviewed a PR team about journalist selection, then built a shared contact database and dashboard with AI assistance. Colleagues continued using it after I moved teams; discovery and qualification components have different maturity levels.

MATURITY

Shared platform

SUPPORTED OUTCOME

Contact database used by PR colleagues

CONTRIBUTION

Built and analysed with AI assistance

The story

The PR team needed to find relevant journalists and maintain a shared contact base. I interviewed colleagues about their selection process: which criteria mattered, how they prioritised them, and what made a contact unsuitable. Their knowledge informed the workflow. I built the software with AI assistance, without a separate developer contributing to the implementation.

The requirement that shaped the architecture was shared editing. A colleague who found a contact needed to add it directly so others could use it. I moved the canonical data store into a backend database and built a dashboard over its API. The documented implementation uses Flask and SQLite, with soft deletion, an audit log and continuous replication to object storage.

Finding new contacts remains a separate workflow. Topic-driven discovery searches beyond the existing database and merges new records through deduplication. Supporting local tools enrich records from author pages and connect journalists, publishers and topics in a graph. The enrichment uses heuristic extraction and keyword matching, so inferred coverage can be incomplete or misattributed.

These parts have different maturity levels. The contact backend and dashboard are deployed; a related qualification component remains partly scaffolded, and some legacy local tools have not been migrated to the backend API. The project does not yet form a complete autonomous outreach system.

I chose shared-token access for a small trusted team. It keeps entry simple but provides no verified individual identity or individual access revocation. A forwarded link exposes access, and rotating the shared token affects everyone. That limitation is part of the design trade-off.

The PR team continued using the database and dashboard after I moved to another team. Continued use is the main result I can support; I have no measured time saving or campaign improvement to attribute to it. Real contact records remain private, so a public demonstration would require entirely invented journalists and publishers.
